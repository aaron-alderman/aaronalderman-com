# Microsite publication process migration

The requested modules contain 12 queries: microsite-projection (3), microsites (5), and microsite-return (4). They are proposed as source/microsites/projection.encounter, publication.encounter and return.encounter.

The readable candidates were composed by the existing sp.moduleView, sp.programme and sp.expression algebra. The three pinned frontend profiles declare their actual statement forms, effects and operators, including the existing one, optional, subjects and objects fact operators. No parser, evaluator, native adapter or kernel change is required.

The ledger captures JSON authority at the recorded baseline. request.json is data for author.run. That workflow must pass ordered module correspondence, whole-module lowering and full candidate validation before it can create source owners, archive exact predecessor bytes, retire the root JSON files and update both build manifests and source-owner bindings. Historical proposals and receipts remain evidence, not independent confirmations.

Inspect already derives its catalogue from the selected processModules. After acceptance, all three sources appear there with exact authored query slices, highlighting, source hashes, generated JSON and compiler coordinates. The viewer renders their effects as source without executing them.
